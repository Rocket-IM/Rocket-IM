## 共同规则

- 默认 E2EE；部署策略可以允许非 E2EE，会话创建时确定模式。一期变更模式需新建会话，不自动迁移旧明文或历史密钥，加密失败禁止明文降级。
- 非 E2EE 仍使用 HTTPS/WSS，明确提示服务器可能读取内容；“公钥加密群”归入 E2EE 机制，不另造第三种安全等级。各模式分别验证正文、自定义内容、附件及元数据边界。
- 登录认证、设备密码身份、历史恢复分开处理。密码重置不能恢复旧密钥；撤销不能收回对方已经保存或解密的内容。
- 不自研密码学原语；安全失败必须明确报错。协议、持久化格式和公开 API 均需版本及兼容策略。
- 按服务实例和账号隔离凭证、密钥、数据库、队列、游标、缓存、事件及推送。所有日志、指标、崩溃报告与备份遵守各模式的数据可见边界，不记录密钥、Token 或 E2EE 明文。
- 完成必须附证据；文档、静态检查、编译、测试、实际运行和安全审计分开记录。没有执行的项目保持 `[ ]`，不能用构建成功代替行为验收。

## 阶段 1：服务与 SDK 的可靠消息闭环

目标：建立可恢复的真实收发链路，稳定消息、密码状态与同步模型。

- [ ] 独立 Go IM Service 可部署，业务身份可通过公开接口映射并换取 IM 凭证；演示登录可替换。完成设备鉴权、Token 续期与撤销、请求限流、大小限制、超时和优雅退出。
- [ ] Service 以 PostgreSQL 事务和唯一约束保证消息幂等、设备信箱一致及 PreKey 并发领取安全；先持久化再返回接受 ACK，明确重复请求、设备 ACK 与信箱清理规则。
- [ ] 验证同步游标与持久化结果一致：并发事务提交乱序不能使游标跳过未同步消息；实时推送与补拉重叠、分页、游标失效及服务重启均可完整恢复。
- [ ] Rust SDK 统一持有每个服务实例与账号的连接、同步及消息状态；重连退避、初始化/关闭幂等、取消订阅、旧连接迟到事件和 FFI 错误受控，界面层不维护第二套消息真相源。
- [ ] Rust 唯一管理四端 SQLite、迁移和事务；宿主只通过公开 SDK 异步读写，全部进入统一读写线程或浏览器等价串行执行上下文。线程分配数量先商议，宿主不直连数据库，数据库工作不阻塞 UI。
- [ ] Rust 的所有数据库读写经显式事务执行，单次查询、恢复读取和迁移均不例外；验证一致性读取、同一业务单元共用事务、事务复用、读写/提交失败及取消后的收尾。读事务结束后交付结果，事务与活动游标不跨 FFI；初始化/维护命令先核对适用边界，不能默认绕过约束。
- [ ] 发送端原子保存密码状态与待发送密文、目标设备和稳定消息 ID；重试复用发送记录，覆盖加密后崩溃、持久化失败及接受 ACK 丢失，避免密钥状态回退或重复加密错误。
- [ ] 接收端原始事件与下载游标共同保存；验证后的业务消息、去重、密码状态、处理结果与处理游标一致提交，再确认设备送达。保留等待依赖、隔离和不可用状态，失败可恢复且不误报送达，重复投递不重复展示，错误密文失败关闭。
- [ ] 收发数据成功入库后才发布对应数据成功回调，失败通过独立错误通道返回；事务外派发，回调内再次异步查询无死锁。验证回调丢失、重复、迟到和订阅重连后经 SDK 查库恢复，订阅与查询衔接不漏变化；本地保存不等于 Service 接受，UI 回调不决定协议 ACK 或双游标推进。
- [ ] 在干净环境部署并执行端到端故障测试：离线、断网、强杀、磁盘/数据库写入失败、服务重启和重复请求；检查数据库、日志及错误上报的 E2EE 明文与密钥泄漏。
- [ ] 阶段出口：文本收发、幂等、事务恢复和增量同步有通过记录；四端最小调用与独立 Service 互通，状态和错误可解释，后续功能无需推翻设备、消息 ID 或同步模型。

产物：可部署 Service、可靠性闭环 SDK、最小 Demo、数据库迁移、自动化与故障注入报告、已知限制。

## 阶段 2：补齐第一期完整功能

目标：按功能清单逐项完成一期 21 项，以下集中检查跨功能风险。

- [ ] 完成会话、消息、历史分页、未读及跨设备同步；删除/清空作用范围明确，删除标记不被旧消息补拉复活；两种模式的界面、API 和 Service 校验一致。
- [ ] 完成多设备默认开启及可关闭、安全绑定、设备签名与列表验证、联系人验证、密钥变化提示；绑定有时效、防重放和失败回收，关闭多设备明确保留设备并撤销其他设备权限。
- [ ] 完成设备撤销与群成员移除的密码保护：以协议确认的变更及新密码状态为生效边界；把此后生成的密文交给被撤销方，验证其旧钥仍无法解密，保留方正常通信；单独验证变更前生成的在途消息规则。
- [ ] 完成多账号并存接收、切换、单账号退出及凭证失效；延迟回调、推送点击、缓存清理和恢复同步不串号，后台能力如实遵循系统限制。
- [ ] Rust 统一管理图片、视频、语音及附件的编码/解码、加密/解密、上传/下载任务及持久状态，完成进度、取消、重试和清理；E2EE 附件先加密再上传，缩略图、封面、临时文件及必要元数据同样受保护，校验失败不保留伪造内容。
- [ ] 提供宿主可配置的最大附件工作数，验证整个处理链的有界调度、背压和账号隔离；计数单位、作用域、总/分项限额及默认值另行商议，不只限制网络请求。耗时任务不占数据库读写线程，文件与数据库提交之间的中断、取消和重启可恢复，未完成文件不得标为可用。
- [ ] 完成推送注册、账号绑定、失效清理、通知开关及免打扰；E2EE 推送载荷无正文和密钥，通知只触发正常同步，交错多账号通知、重复和丢失推送均不破坏消息一致性。
- [ ] 完成本地数据库与缓存保护、平台安全存储和账号清理；锁定新设备、换机、重装及全部设备丢失的历史策略，授权迁移/加密备份失败不覆盖现有数据，不宣称密码重置可恢复旧历史。
- [ ] 完成好友申请、接受/拒绝、拉黑和陌生人权限，以及群角色、审批、转让、退出、移除和解散；Service 强制权限，E2EE 群成员变更具备可验证版本，测试恶意加人、旧状态覆盖、并发变更和群状态分叉。
- [ ] 完成详情操作、自定义消息及必要管理能力；举报仅主动披露用户确认选择的证据，并验证来源、保留与删除规则。E2EE 管理端无全局解密能力，系统通知使用独立可验证身份，后台不能冒充普通用户。
- [ ] 阶段出口：一期 21 项逐项关联证据，两种模式的单聊/群聊、附件、多设备、多账号、好友权限、举报及历史策略通过自动化和实际运行验收；未完成项不得以一期已完成对外发布。
