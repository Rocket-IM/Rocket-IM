# 项目文件结构

更新：2026-09-15。状态：已有隔离密码探针、实验协议源、本机网络 Relay、跨进程验证，以及不依赖POC的Rust内存核心、四端最小包及五运行端交叉互通实验，并新增隔离浏览器普通记录与真实 OpenMLS 密码事务实验。正式IM业务与Service仍未实现；实验包不代表完整IM SDK发布。

2026-09-15 根据用户纠正：“四端”指 Flutter、Swift、Kotlin、TypeScript 四种 SDK 语言交付，不等于四种操作系统。TypeScript 主要面向 macOS/Windows 桌面客户端，浏览器次要；原 TypeScript 包的浏览器实测记录保留；随后新增的 Node 目标包复用 `bindings-wasm`，桌面宿主运行另行记录，不改写历史浏览器结果。

新增文件遵循本文；职责见[交付物与技术栈](交付物与技术栈.md)，范围见[功能分期与验收](功能分期与验收.md)，实施顺序见[开发路线与检查清单](开发路线与检查清单.md)，协作规则见 [AGENTS.md](../AGENTS.md)。

2026-09-24 首次 Git 入库范围：`api/`、`src/`、`poc/`、`tests/`、`tools/`、`docs/`、根目录 `README.md`、`AGENTS.md`、`.gitignore` 与 `.gitattributes`。保留模块清单、锁文件、工具链配置和现有 FRB 生成源码；`.gitattributes` 保留既有生成许可证清单的原始换行字节，避免 Git 自动转换改变历史摘要。忽略 `dist/`、依赖安装目录、各模块构建缓存及本机状态。`dist/` 中的历史报告、失败轮、源码快照与包仍保存在本机，不因忽略而删除；现有相对链接保留为本地定位记录，新克隆不能直接访问，在线证据归档尚待安排。此边界不改变下列代码归属及既有验收结论。

## 3. 职责与依赖方向

| 位置 | 依赖与边界 |
|---|---|
| `src/apps/*` | 普通 Demo 只使用对应公开客户端 SDK；管理后台只调用公开管理 API。演示账号由 `examples/business-backend/` 提供，不把注册业务塞入客户端 SDK。 |
| `src/sdk/{flutter,swift,kotlin,typescript}` | 封装语言 API、系统能力及对应 Rust 绑定；提供网络、存储及执行环境适配，不直接开库或执行 SQL，不重新实现消息、同步、密码或附件任务规则。宿主通过公开 SDK 查询、命令和事件访问，平台不维护第二套消息数据库。 |
| Rust `bindings-*` crate | 只做桥接、类型/错误转换与资源管理，调用 `im-sdk`；不形成多套 IM 引擎。当前三个 crate 对应既有路线，`bindings-wasm` 供Web/Node分别生成绑定；最终桌面原生桥接待评估。 |
| `im-sdk` / `crypto-core` | `im-sdk` 统一管理账号引擎、四端 SQLite 本地数据和附件任务，使用 `crypto-core` 提供的密码能力；后者不依赖 UI、Demo、Go Service 实现或平台 SDK，第三方密码库类型不穿透为公共 API。 |
| `src/backend/` | 协议入口调用业务能力，业务能力通过所需接口使用存储和外部服务；`cmd/im-service/` 负责装配。Go 后端与独立 Service 是同一实现及其运行产物，不另建第二套 `src/service/`。 |
| `src/server-sdk/go/` | 仅封装公开 HTTP API 与 Webhook 接入，不导入后端 `internal` 包、不直连 IM 表、不复用用户解密私钥。示例业务后台使用此 SDK 或公开 API。 |
| `api/` / `deploy/` | `api/` 是公开协议定义的源头；各端实现遵守契约。`deploy/` 只装配和配置产物，不承载业务逻辑。 |
| `poc/` / `tests/consumers/` | POC 不成为正式运行依赖；消费工程只依赖 Release 发布包和公开 API，不用源码路径依赖代替接入验证。 |

目标平台：Flutter 面向 iOS/Android，Swift 面向 iOS，Kotlin 面向 Android，TypeScript 主要面向 macOS/Windows 桌面客户端、浏览器次要。当前最小消费使用 Node 工作线程与预编译 Rust WASM；具体系统运行结果见[四端最小发布验证](四端最小发布验证.md)，不能外推为 Electron/Tauri、完整桌面客户端或 Windows 已通过，也不增加 Flutter Web 等目标承诺。

## 4. 模块、生成文件与测试

- **模块清单归模块。** Go Service 与 Go 服务端 SDK 各有 `go.mod`；Rust workspace 与 crate 各有相应 `Cargo.toml`；Flutter、Swift、Kotlin、TS 各在所属目录维护生态清单、锁文件及构建配置。按实际版本和发布方式建立，不假设根目录存在统一构建命令。
- **手写源与生成结果分开。** SQL 定义在 `src/backend/db/queries/`，生成访问代码归 `internal/storage/` 下明确标识的生成目录；桥接定义在对应 Rust crate，生成的语言绑定归对应平台包。生成配置写明输入、输出与版本，只修改生成源。
- **发布包包含所需绑定和二进制。** Flutter/Swift/Kotlin/TS 使用者无需 Rust/Cargo 或代码生成器。平台包的源码、加载配置、发布描述归 `src/sdk/*`；原生库、XCFramework、AAR、WASM、镜像等临时输出归 `dist/`，最终按发布流程附入包或托管，不能只靠开发者本地文件。
- **本地状态跟随所有者。** 四种 SDK 语言交付及其目标平台（含 TypeScript 桌面与浏览器）的 SQLite 连接、表结构、迁移、事务与读写调度均归 `im-sdk`；全部数据库读写必须走显式事务，包括单次查询、恢复读取和迁移，一致性单元共用事务句柄。统一读写线程的数量及实例/账号分配待明确。桌面与浏览器分别提供持久化与执行环境适配；浏览器已采用的 OPFS/Worker 实验不作为桌面前置，不另建业务数据库。读事务正常结束后交付结果，写入成功事件在提交成功后、事务外派发，失败仍明确回报；活动数据库资源不跨 FFI。初始化与维护命令边界见[端侧存储与附件管理](端侧存储与附件管理.md)。Service 迁移只放 `src/backend/db/migrations/`，两者不可混用。
- **附件任务跟随账号引擎。** 编解码、加解密、上传下载及任务状态归 `im-sdk`；必要的平台能力通过适配接入。宿主通过公开 SDK 配置最大工作数，统计口径、作用范围与默认值待明确；耗时附件处理和网络等待不占用 SQLite 读写线程。详细约定统一见[端侧存储与附件管理](端侧存储与附件管理.md)。
- **模块测试随模块。** Go `_test.go` 靠近实现；Rust 单元测试及 crate 集成测试归各 crate；Flutter/Swift/Kotlin/TS 按各自工程惯例放测试。单个 Service 的数据库集成测试仍归 `src/backend/`，跨组件流程才归根 `tests/`。
- **验证材料按用途归档。** 协议向量归相关密码/协议模块，跨端测试数据归 `tests/`；容量、故障和升级验证脚本按是否跨组件分别放模块测试或根 `tests/`，共用工具放 `tools/`。不提交凭证、真实用户数据、运行数据库、缓存或临时构建目录。
