## 1. 范围与路线

代码在 `poc/browser-storage/`，不修改已经验收的四端内存核心及包。使用 `rusqlite = 0.40.1`、`sqlite-wasm-rs = 0.5.5`、`sqlite-wasm-vfs = 0.2.0`，独立 Cargo.lock 固定传递依赖。SQLite C 实现与 Rust 编译进同一个 WASM，显式选择 SAH pool OPFS VFS，不使用默认内存 VFS或 IndexedDB 业务数据库。原生端与正式 SDK 尚未采用这些候选依赖。

选择原因：Rusqlite 提供显式事务与 SQLite 错误；该 WASM 绑定可使用现有 Rust 与 NDK clang 工具链；SAH pool 可在 Dedicated Worker 使用真实 OPFS 同步文件句柄，无需 COOP/COEP。另一路线是官方 SQLite WASM 加 JS C API 环境桥，当前先验证直接 Rust 绑定。VFS 维护者仍将实现称为实验性，故本次通过不能直接定为正式平台承诺。[Rusqlite 版本清单](https://github.com/rusqlite/rusqlite/blob/v0.40.1/Cargo.toml)、[WASM 绑定维护者说明](https://github.com/Spxg/sqlite-wasm-rs)、[VFS 0.2.0 源码](https://docs.rs/crate/sqlite-wasm-vfs/0.2.0/source/src/sahpool.rs)。

三个候选 crate 均声明 MIT，SQLite 为公有领域；传递依赖的独立声明与文本须继续核对，不能据此直接批准整个包发行。[SQLite 版权说明](https://sqlite.org/copyright.html)。首轮 `q05.1` 锁定 69 包（含本实验包），保守采集 68 个第三方包与 99 份许可原文；其中 15 个归档未附原文，保持 `REVIEW_REQUIRED`，公开发行未评估。

- 每个服务实例/账号对应一个独立 Worker、一个连接与一个独立 OPFS 池目录；名称含分段长度，避免账号与服务名拼接冲突。此为本次 POC 的明确选择，不替原生端锁定线程模型。
- Web Locks 排他占用同一范围；第二页面明确返回 `IN_USE`，关闭原持有者后可接管。不开多标签共享引擎，不无限等待。数据库读写只在 Rust 同一个 Worker 串行执行。
- 服务名、账号、记录 key 为 1—64 位安全 ASCII，value 最多 4096 UTF-8 字节，每范围最多 128 条，最多 64 个排队/活动命令。revision 使用无损的 u64 十进制字符串，写入提供 `expectedRevision`。
- Rust 完成表结构、迁移、读、写、恢复及关闭。所有 SQL 经显式事务；读事务结束才返回值；写事务提交且清理成功后才交付成功。结构迁移与版本号同一事务。TS 不持有数据库、SQL或另一份业务状态。
- `subscribe` 在同一队列中完成初始快照与监听注册，随后只接收已提交快照；回调可以重新查询，SDK 不等待宿主回调。关闭拒绝未交付请求，清理监听，忽略迟到响应。
- SQL 错误、提交未确认、Worker 超时或异常使范围暂停或失效，只有关闭后新建 Worker 才能重开。不自动重发写入；普通数据可重查确认，不能推导为密码状态可直接重用。
- VFS 初始化中途可能遗留部分同步句柄。开库失败、trap 或关闭失败后终止整个 Worker，再释放页面占用；不在原 Worker 重试。该库 OPFS 元数据损坏、迭代器错误路径仍需专项审查和复现。

首轮只验证选定 Chrome 环境中的普通记录存储路线；当时尚未验证真实 MLS 共同提交。随后取得的局部证据见第 6 节。原生 SQLite、真机生命周期、Safari/Firefox、断电/磁盘故障、长期后台逐出或恶意宿主仍未验收。站点数据清理后本 POC 可创建空普通记录库；正式密码范围必须使用已有安全重建规则，不能把旧身份当新空库继续工作。

## 6. 真实 OpenMLS 与 SQLite 共同提交

### 6.1 范围、依赖与维护边界

本轮扩展同一 `poc/browser-storage/`，使用新生成的实验身份、双成员群与合成消息，不读取真实用户密钥。`src/crypto/` 分开引擎适配、完整 provider 快照、结构校验、请求、事务、查询与候选操作；复用既有 Rust SQLite 连接和显式事务入口。普通记录与密码门面共用 Worker 调度、队列、关闭规则和同一服务/账号排他锁。未修改原 `src/sdk/` 内存核心、旧密码 POC 或 Relay。

依赖固定为 OpenMLS `0.9.0`（`js` 特性）、`openmls_basic_credential` / `openmls_rust_crypto` / `openmls_traits` `0.6.0`、`getrandom 0.2.17`（浏览器随机环境）、`sha2 0.10.9`（状态和幂等摘要）、`base64 0.22.1`（公开二进制编码）。它们沿用本项目已验证的 OpenMLS 系列版本；已有普通存储依赖的版本组合全部保留。密码套件固定为 `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`，未自研密码算法。

选择完整 provider 快照，是为了把 OpenMLS 实际保存的秘密树、群状态、签名身份及 KeyPackage 等记录一起纳入事务。只保存 `MlsGroup` 表面字段或模拟计数器不够。此适配依赖 `openmls_memory_storage` 的内部表示，格式显式绑定 OpenMLS/provider 版本；升级需要迁移与重新验收，不能直接换库。替代方案是实现完整 SQLite `StorageProvider`，当前没有引入这一层更大的适配工作。OpenMLS 将持久层视为可信来源，并要求秘密删除具备相应保证；普通 SQLite/OPFS 的事务通过并不满足这些全部要求。[OpenMLS 持久化说明](https://book.openmls.tech/user_manual/persistence.html)。

OpenMLS 系列声明 MIT；上述随机、摘要和编码依赖声明 MIT OR Apache-2.0，以包内精确锁文件采集记录为准。本轮锁定 232 包（含本实验包），采集 231 个第三方包、368 份许可原文；49 个归档未附可采集原文，包括本轮 OpenMLS 归档，保持 `REVIEW_REQUIRED`。全部缓存归档摘要匹配，0 个采集致命错误，公开发行仍为 `NOT_ASSESSED`。这份材料包含构建及其他目标依赖，不能当作精简运行时 SBOM。

**只验证新生成的实验秘密。** 完整 provider 作为 Rust 内部 BLOB 写入 SQLite，本轮没有给数据库或 BLOB 加密，也没有实现浏览器秘密包装、内存零化或旧页安全擦除。JS 公共接口只接收公钥身份、信封、消息投影及摘要，不接收私钥或 provider；这不构成对恶意宿主脚本或存储读取者的防护。当前包不能用于真实账号。

### 6.2 事务与失败规则

- 每个服务/账号一个测试设备、一个双成员群。打开时仅检查或创建空实验结构，必须显式 `initialize` 才生成新身份；不会因为打开或发送请求自动补建身份。
- 密码操作先在显式写事务中核对无未决预约、输入/幂等/容量及当前 revision，提交包含操作、尝试 ID、输入摘要和旧 provider 摘要的预约；确认预约提交后才导入或调用 OpenMLS。密码计算在 SQL 事务外完成，临时候选出错后丢弃。
- 最终显式写事务再次核对预约、revision 和旧 provider 摘要，将完整新 provider、结果投影和操作日志一起保存，并在同一提交中删除预约。发送结果包括稳定尝试和准确密文字节；相同已提交尝试返回原密文，内容冲突明确拒绝。没有任何成功密文在提交前穿过 FFI。
- 接收分两步：`download` 只把原始信封和连续下载游标共同提交，不导入 MLS，也不生成密码预约；`processNext` 再按预约协议验证下一条，将去重、真实密码状态、消息、回执事件和处理游标共同提交。重复完整已验证信封只推进新事件槽，不重复解密、消息或回执；序号缺口或内容冲突明确拒绝。
- 预约后失败或崩溃留下持久未决记录，关闭/重开、重试旧已完成尝试也不能绕过它。`inspect` 可读已提交状态，不能解锁、恢复旧 provider 或重新加密。本轮不提供重建/解锁接口。预约本身提交失败且确认回滚时，尚未调用 MLS；关闭后可重开确认无预约再执行。
- 已完整提交但响应/通知丢失时，重开读取完整结果，发送仅复用保存的密文。公开 `committed` 事件在最终事务结束后派发，查询回调可重入；检查点只发 `testOnly` 阶段标记。
- 已有密码空间必须含完整 7 张表及唯一合法元数据行。控制表缺失时明确拒绝打开，绝不通过自动补表解除未决状态。全部站点数据消失仍不能靠本地判断首次使用与丢失；空库不自动产生身份，但显式创建新身份不是正式恢复方案。

`crypto_reservation`、日志和 provider 都在同一个数据库内。日志摘要是记录，不是认证存储，也不是独立反回滚锚。整个数据库恢复成旧的完整已提交版本时，本轮尚不能发现；必须先解决独立锚和恢复契约，不能把本项写成完整 Q05 通过。

### 6.3 公开实验接口

包升级为 `@rockets-im/browser-storage-probe@0.1.0-q05.2`，仍是私有实验包。`openCrypto({service, account, testMode?})` 返回 `inspect`、`initialize`、`createGroup`、`joinGroup`、`send(attemptId, messageId, text)`、`download(event)`、`processNext`、`subscribe` 和 `close`。`ready` 只表示没有持久未决记录，不代表生产身份可信；当前句柄遇到提交等错误后还需关闭重开。公开错误保留原因，失败不会降级明文或内存。

标识符为 1—64 位安全 ASCII；消息非空且最多 4096 UTF-8 字节；协议二进制最多 64 KiB，使用规范 Base64。每范围 outbox、原始事件及消息各最多 32 条、操作日志最多 128 条；计数与双游标均为无损十进制字符串。provider 快照最多 2 MiB/4096 项。公开快照只含拥有所有权的值，outbox/回执使用稳定排序，活动事务、游标及 OpenMLS 类型不跨绑定。

`testMode` 才允许候选密码操作后失败、SQL 写后真实缺表错误、SQLite commit hook 拒绝、预约提交拒绝和四个中断检查点。`lose_reservation_table` 仅限测试 `send`：预约提交后、MLS 调用前，在独立事务删除固定控制表，以验证重新打开必须报损坏；它不是公开 SQL 入口。所有故障均在本次新建测试数据中执行。

### 7.1 数据、信任与恢复边界

`AnchorProbe` 是与原普通记录及未锚定密码实验并列的独立入口，业务实现仍复用同一个 Rust 密码存储模块。每个服务/账号由同一 Worker 队列、范围锁及 Rust 连接持有；网络等待前已结束 SQLite 事务。TypeScript 只做参数、生命周期及有界 HTTP 适配，不打开数据库，不计算或接受密码状态。

摘要采用固定域、表名、列数、类型标签、长度和确定排序；包含全部 `crypto_*` 表结构及业务数据，包括完整 provider 字节。每表最多 128 行、单值最多 2 MiB、总字节最多 8 MiB，超限明确失败。协调门禁/完成日志不参与自身摘要，另用成熟 Ed25519 实现签名，绑定可信配置指纹、随机事务号、基线摘要、操作摘要、已确认预约 revision、目标摘要和结果摘要。直接依赖 `ed25519-dalek = 2.2.0` 是复用已有传递依赖版本（BSD-3-Clause），用于与旧锚协议一致的签名及验证；未引入自研算法或升级旧锁定包。维护与分发仍须遵循依赖清单的审查状态。

| 窗口 | 允许的行为 |
|---|---|
| 首次预约前失败，远端确认没有未决且仍为同一完整基线 | 保留门禁；调用方显式 `resume` 后才可另启命令 |
| 预约回复丢失、预约后崩溃或密码/SQL 失败，没有完整候选日志 | 持续暂停；不重做 MLS、不恢复旧 provider、不以旧缓存解锁 |
| 候选与签名日志已同事务保存，Finish 尚未确认 | `status` 仅返回诊断；显式 `resume` 只完成同一事务、同一目标，不调用 MLS |
| Finish 已落盘但回复/本地收尾丢失 | 仅接受签名响应中的精确重复完成、目标及 revision；本地复核清门禁后才允许后续读取 |
| 完整旧库与当前锚不一致 | 新命令、缓存读取、订阅均拒绝；诊断不返回消息、密文或 Welcome |
| 浏览器与锚一起恢复到匹配的旧版本 | 此模型无法发现，必须记为 `EXPECTED_UNDETECTABLE`，不能据此宣称全局新鲜性 |

`status` 和 `resume` 成功响应的 `snapshot` 固定为 `null`；只有锚确认并且本地再次核对完成后，业务返回值及订阅事件才含密码快照。SQLite 明确报告提交/清理失败时仍须关闭重开，不能靠恢复接口消除连接错误。

锚复用 `rim-rollback-anchor-1` 签名原文、请求摘要和新随机 challenge；Reserve/Finish 使用十进制字符串 revision 的 CAS，范围同时绑定服务、账号、设备、公钥和 store_id。独立 Node 进程用 SQLite 事务保存状态；仅允许固定 loopback 地址的有界请求，客户端禁重定向，适配器不实现重试，3 秒超时，请求/响应上限 32 KiB。浏览器网络栈仍可能重发，协议不能以一次公开调用等于一次服务端执行为前提。这是测试工具，不是正式 Go Service 或生产锚服务。

必须保留的信任条件：浏览器外控制器持有可信配置，并在登记后始终选择 `openAnchored`。同一实验包保留旧入口供历史回归；库内标记可阻止已绑定数据库被旧入口误开，但标记本身会随库回滚。恢复首次绑定前备份后主动改用旧入口、替换应用代码/包或修改可信配置，属于本轮尚未实现的客户端策略保护，不能声称由可回滚的数据库标记解决。WASM 也不是对恶意宿主脚本的秘密隔离。

## 8. 浏览器未决范围安全重建

用户随后明确“继续下一步”，本项已实现并完成下述局部验收；第 7 节末尾的建议状态为历史。本轮仍是本机合成实验，不启动正式 SDK 或 Service。

固定范围：服务与账号不变，新设备 ID、公钥、客户端认证钥和物理存储空间均不同。先显式创建仅含新身份的候选，未取得独立批准并完成锚关联前禁止群和消息操作。批准公钥在旧范围首次登记时固定，批准私钥由浏览器外的合成控制器持有；它是本轮明确标识的恢复批准来源，不冒充旧 Unix 实验的真实设备批准、权限链或生产用户核验。

密码失败已插入本地预约时，重建前在 Rust 显式只读事务中核验签名门禁和预约字段，并用相同完整摘要算法投影“预约之前”的状态；只在内存摘要中把唯一预约行视为空，不删除数据库行、不加载旧 provider 或执行 MLS。已有完整完成日志优先走原精确恢复，不能用重建覆盖已保存结果。

### 8.1 公开入口、持久状态与批准

实验包版本为 `0.1.0-q05.4`。旧锚客户端新增 `rebuildBasis()`，只返回经核验的旧范围、未决事务、revision、群与摘要；不交付消息、密文、Welcome 或密码状态。新入口为 `createRebuild(options)` 和 `openRebuild(options)`：前者必须显式 `testMode: true`，后者只打开既有候选，缺库不创建身份。两者共用 Rust 数据库线程与 Worker 队列；原范围和新范围使用不同的物理目录及 Web Lock，新范围的 `storageNamespace` 必须等于签名范围的 `store_id`。

新客户端公开 `offer/status/activate/resume/joinGroup/send/download/processNext/inspect/subscribe/close`。候选不能创建群，必须经批准后接受计划中指定对端的真实 Welcome。`offer/status/activate/resume` 只返回诊断与候选公开材料，`snapshot` 恒为 `null`；业务快照及成功订阅仍须完成独立锚和 SQLite 提交。

| 状态与中断窗口 | 处理契约 |
|---|---|
| 创建候选前 | 先持久保存该命名空间的占用和配置绑定，再执行一次新身份初始化 |
| 新身份候选失败或 SQL/提交失败 | 保留已存在的控制记录及预约；同命名空间不能再次创建，重开不重新生成身份 |
| 新身份已完整提交、公开 offer 未保存 | 重开仅从已提交身份与完整摘要补齐签名公开 offer，不执行密码初始化 |
| 候选尚无批准 | 允许查看公开材料；群、消息、缓存读取与订阅均拒绝 |
| Link 请求前 | 在新库保存绑定完整计划的签名批准意图；结果未知后不能换计划 |
| Link 提交前失败 | 旧范围仍保持原未决；显式恢复只能提交原计划 |
| Link 已提交、回复或本地收尾丢失 | 旧范围已封存；重开或显式恢复只能确认同一后继。远端后继已推进而本地仍是未关联初始候选时拒绝 |
| 完成关联但尚未入群 | 无历史、无业务快照；只允许加入批准的新群和对端 |
| 入群及后续收发 | 复用第 7 节预约、原子提交及准确结果恢复；发生未决密码操作仍持续暂停 |

Node 锚的格式 1→2 升级只增加批准公钥和唯一后继关系，不改变原 registry 的任何记录，也不自动登记批准公钥。格式 2 缺少任一控制表视为损坏，拒绝补表继续。旧范围关联后，普通 Inspect/Reserve/Finish 均返回签名封存状态，包含原预约的重复请求也不能解除封存。恢复批准、客户端请求和锚响应分别使用固定签名域；响应绑定完整计划摘要、本次请求摘要和新随机 challenge。

本轮批准是浏览器外控制器的 `synthetic_local` 明确批准。批准私钥、锚状态和浏览器 profile 分目录保存；这不等于生产独立故障域。创建新身份不自动赋予旧历史或生产群权限，客户端认证种子也不因此获得浏览器安全存储保证。
