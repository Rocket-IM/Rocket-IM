# 交付物与技术栈

更新：2026-09-15。状态：交付规划；已有四端内存实验包，尚无正式业务实现或公开发布的完整 SDK。隔离 POC 的有限运行结果见[密码方案验证](密码方案验证.md)及[浏览器存储验证](浏览器存储验证.md)。功能和验收见 [功能分期与验收](功能分期与验收.md)，工程步骤见 [开发路线与检查清单](开发路线与检查清单.md)。

2026-09-15 根据用户纠正：本文“四端”指 Flutter、Swift、Kotlin、TypeScript 四种 SDK 语言交付，不等于四种操作系统。TypeScript 主要面向 macOS/Windows 桌面客户端，浏览器为次要目标；目标是为 Rust SDK 提供 TypeScript 接口与对应运行产物，业务与密码状态继续由 Rust 管理。已有 TypeScript 浏览器包与 POC 只证明原实测矩阵。本次桌面最小产物选用 Node 宿主与 wasm-bindgen `nodejs` 目标，复用独立 Rust 内存核心；本文不记录本次运行通过结论，Windows 尚未实测，最终桌面应用宿主与持久化方案未定。

## 1. 产品与接入边界

- 提供独立部署的 **Go IM Service**、不含 UI 的 **Rust 客户端核心**，以及 Flutter、Swift、Kotlin、TypeScript 发布包。
- 第三方安装 SDK、部署 Service，通过公开接口接入自己的业务；正常使用不需要 fork、修改 Go/Rust 源码、复制 Demo 或直接读写 IM 数据表。
- 接入方负责业务身份对接、SDK 初始化、自有 UI、系统权限和推送配置；Service 可采用模块化单体，但独立运行、部署和升级。
- 首期采用中心化、单租户、单实例部署；多设备默认开启并可关闭，多账号可同时登录并接收消息。
- E2EE 默认开启并允许关闭；会话创建时固定安全模式，首期改变模式需新建会话。公钥加密群属于 E2EE，具体机制需验证。
- 目标平台：Flutter 面向 iOS/Android，Swift 面向 iOS，Kotlin 面向 Android，TypeScript 主要面向 macOS/Windows，浏览器次要。TypeScript 本次仅验证 Node 可消费的最小 SDK 包，最终 Electron/Tauri 等桌面应用宿主及原生绑定仍待评估；Flutter Web 及其他目标不据此增加支持承诺。
- 服务端 PostgreSQL、四端由 Rust 管理 SQLite，以及 Rust 管理附件处理与传输是已确认方向；正式SDK的具体数据库绑定、媒体依赖及调度实现仍需商议；隔离浏览器POC已采用SQLite/OPFS与Worker，正式整合仍待完成。其余库为建议基线；密码协议、版本、最低系统要求与 CPU 架构须通过验证后锁定。

| Go IM Service | 容器镜像、独立可执行文件、配置模板、数据库迁移入口和运维文档 |

Flutter、Swift、Kotlin、TypeScript 使用者无需安装 Rust/Cargo、运行代码生成器或编译 Rust 核心，只需正常构建自己的移动 App、桌面客户端或网页。Service 使用者无需 Go 工具链。

预编译与绑定生成由项目发布流程完成；产物缺失、不匹配或校验失败必须明确报错，不能隐式改为源码编译。源码构建是维护者或高级使用者主动选择的独立流程。

## 3. 身份、数据与运行职责

标准接入：部署 Service；业务后台校验原有账号并取得受限 IM token；客户端向 SDK 提供地址和 token，完成设备授权、连接和收发；UI 使用 SDK 查询与事件。

| 归属 | 职责与边界 |
|---|---|
| 接入方业务系统 | 保留业务账号及订单等数据；通过公开 API 维护 IM 用户映射与业务联动 |
| Go Service | 管理 IM 用户、设备/公钥目录、投递权限、消息持久化、收件记录和迁移；E2EE 内容仅保存密文 |
| Rust 核心 | 唯一持有端侧 SQLite，负责连接、结构、迁移、事务与统一读写线程；管理消息、队列、同步、游标、密码状态，以及附件编解码、加解密、上传下载和任务状态 |
| 平台适配层 | 提供必要的网络、文件访问、运行环境、系统安全能力、推送与生命周期适配；不另开消息数据库或建立第二套附件任务引擎 |
| 宿主 UI | 通过公开 SDK 提交操作、查询已提交数据、订阅事件并配置附件工作数；不直接打开 SQLite、执行内部 SQL 或自行维护核心消息状态 |

核心按 **服务实例与账号** 隔离会话、数据库和密钥命名空间，支持多账号并存；用户与设备分开建模，多设备各自维护密码身份与同步状态。

IM token 证明服务访问权限，不等于设备的 E2EE 身份，也不能自动恢复历史解密能力。管理凭证只放可信后台；用户私钥和会话密钥由端侧持有，Service 的认证签名密钥另行管理。

消息与相应状态先成功提交 SQLite，再在事务及临界区之外通知宿主；宿主通过公开 SDK 发起的后续查询和业务写入仍进入统一读写线程。失败通过明确错误通道回报，回调内查库不能死锁，丢失或迟到通知不能破坏已提交状态或账号隔离。

Rust 的全部数据库读写必须通过显式事务，包括单次只读查询、恢复读取及迁移中的数据/结构操作；一致性单元共用事务句柄，不按每条 SQL 拆散提交。读事务正常结束后返回结果，写事务提交后派发对应成功事件；不向宿主暴露事务或活动游标，初始化与维护命令边界按专项文档另行核对。

附件的耗时编解码、文件处理与网络传输由 Rust 独立调度，不占用数据库读写线程或事务等待。公开 SDK 支持设置最大附件工作数；计数单位、作用域、总上限与分项限额、默认值及运行时调整尚待商议。具体边界统一见[端侧存储与附件管理](端侧存储与附件管理.md)。

## 4. 技术方向与建议依赖

| 层级 | 技术 | 职责 |
|---|---|---|
| Service | Go、net/http + chi | HTTP 路由、鉴权、限流、超时与错误响应 |
| 实时连接 | coder/websocket | WSS、心跳、确认、有界队列与连接关闭 |
| 服务端存储 | PostgreSQL 已确认；pgx/pgxpool 为建议依赖 | 持久化、连接池、SQL 与事务 |
| 数据工具 | sqlc、goose | 开发期生成类型安全访问代码；数据库初始化与升级迁移 |
| 原生客户端核心 | Rust、Tokio、Serde | 共享业务引擎、异步运行与序列化 |
| 端侧本地存储 | 四端 Rust + SQLite 已确认；原生绑定待定，隔离[浏览器普通记录与真实OpenMLS持久化实验](浏览器存储验证.md)已执行，正式SDK整合待完成 | Rust 管理消息、密码状态、待发送记录、游标、附件任务与本地迁移，读写统一调度 |
| 端侧附件管理 | Rust 统一实现与调度；媒体库和系统能力适配待商议 | 编解码、加解密、上传下载、取消、重试及清理；宿主可配置最大附件工作数 |
| Flutter 绑定 | flutter_rust_bridge | Dart API、事件和预编译库桥接 |
| Swift/Kotlin 绑定 | UniFFI | Swift/Kotlin API 包装与原生库桥接 |
| TypeScript 桌面绑定 | 本次最小包：Node + wasm-bindgen 0.2.128 `nodejs`；最终应用宿主与原生绑定待评估 | 公开 JS/TS 接口调用预编译 Rust 内存核心；同步操作由宿主放入 Node 工作线程。本包未实现 SQLite，后续业务、SQLite 与密码状态仍归 Rust |
| 浏览器绑定 | wasm-bindgen、WASM | JS/TypeScript API；Rust 管理 SQLite，浏览器持久化介质、Worker/串行执行环境及多标签页访问单独验证 |
| Flutter Demo | Flutter、Dart、Riverpod、go_router | 示例界面、页面状态与导航，不成为公共 SDK 的强制依赖 |
| 可选管理后台 | Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus | 管理界面、状态与路由，只调用公开管理 API |
| 部署与发布 | Docker/Compose、Caddy、GitHub Actions | 安装与持久卷、HTTPS/WSS、构建打包与版本发布 |

各平台 API 业务语义一致，同时遵循各语言的异步、错误和资源管理习惯；桥接工具不替代 API 设计、系统适配和发布验证。TypeScript 桌面与浏览器分别适配运行环境，浏览器 OPFS/Worker 路线不作为桌面前置。本次 Node 包共享已有 Rust 导出源与锁定依赖，不新增 napi-rs；生成 CommonJS 绑定、预编译 WASM 和类型声明，再配套独立 ESM 公开门面，具体生成方式见[端侧代码生成](端侧代码生成.md)。此选择不把 WASM 定为最终桌面绑定，也不把 Node 运行等同于 Electron/Tauri 应用验收。浏览器不能直接套用原生 Tokio、文件存储或硬件安全能力；IndexedDB 等若参与评估，仅是 SQLite 底层持久化适配的候选，不另设一套消息业务数据库。浏览器持久化不可用时须明确失败，不静默改成内存保存。

## 5. 密码模块与可靠性

2026-09-14已有独立Rust内存核心与四端最小包实验，使用OpenMLS0.9.0、UniFFI0.31.0、FRB2.11.1和wasm-bindgen0.2.128验证预编译路线。精确版本、实际消费结果和限制统一见[四端最小发布验证](四端最小发布验证.md)。这些是本地实验选择，不代表正式密码/许可证决策已通过，也没有把隔离POC中的同步、历史和恢复能力接入SDK。

随后隔离浏览器POC在普通记录持久化之上增加真实OpenMLS状态与待发送密文共同提交、接收消息与去重/处理游标共同提交，以及下载记录/下载游标的独立一致保存；持久未决预约在失败或中断后阻止继续密码操作，结果详见[浏览器存储验证](浏览器存储验证.md)。这项能力尚未整合到四端内存SDK，同库预约不能防全库回滚，秘密保存与安全删除尚未验证，Q05、T09/T10及完整阶段0继续开放。随后新增 `synthetic_local` 独立锚入口及完整候选的精确恢复，见[浏览器存储验证第 7 节](浏览器存储验证.md#7-浏览器独立锚与恢复契约)；生产独立保存与可信入口保护仍需验证。随后在同一本机合成信任边界内增加未决旧范围封存、独立批准的唯一新身份/存储空间与新群互通，结果和限制见[浏览器存储验证第 8 节](浏览器存储验证.md#8-浏览器未决范围安全重建)；生产恢复批准与旧历史迁移不在本项内。

- 密码库仍待选：本轮在隔离 POC 中比较 vodozemac 的 Olm/Megolm 与 OpenMLS 的 MLS 成员变更；libsignal 和 matrix-sdk-crypto 保留为资料候选。精确版本、许可证、引入原因与已知限制统一见[密码方案验证](密码方案验证.md)。正式采用前验证维护、身份信任及四端兼容，不自研算法，不把两个候选共同接入正式 SDK。
- 先验证离线首条消息、身份验证、乱序/重复/篡改、崩溃恢复和目标平台，再锁定方案；模块隔离不代表能无损更换密码协议。
- 发送前在同一 SQLite 事务持久化密码状态与待发送密文，重试复用已存记录；接收时在同一事务提交去重、密码状态、消息与相应游标。对应成功提交后再通知宿主，不能以“可恢复”为由拆散库内一致性单元；SQLite 外的安全存储、文件或独立锚另行定义恢复协议，也不能仅回滚 SQL 后继续使用已推进的密码内存状态。
- 端侧秘密加密持久化；移动端通过 Keychain/Keystore 保护合适的秘密或包装密钥，浏览器单独定义脚本信任边界。
- Service 持久化成功后才确认；入库后实时投递中断，应能离线补齐。持久化确认、设备送达和已读分别建模，通过幂等与去重处理重复。
- SQLite 事务不天然覆盖附件文件和远端上传结果；文件、数据库记录与远端操作须有中断核对和恢复规则。上传完成、消息被接受、附件本地可用分别通知，不能用瞬时进度代替持久成功状态。
- E2EE 保护正文和附件；非 E2EE 模式下服务器可能读取内容，UI 必须标识。两种模式均使用 HTTPS/WSS，服务器仍可观察路由、时间、大小、IP 等元数据。
- 日志与诊断不得记录私钥、token 或消息明文；服务端备份不能替代历史密钥恢复。设备撤销和移出群后的解密边界按功能文档验收。

## 6. Demo、后台与扩展

- Flutter、Swift、Kotlin、TypeScript 桌面与浏览器 Demo 均按对应目标提供演示注册/登录与必要验收入口；全部使用 SDK 公开 API，不访问内部库或私有实现。桌面示例随宿主路线确定后实施。
- 可选后台覆盖管理员权限、用户/设备/群、配置、配额、封禁、举报、审计及运行状态；不提供通用 E2EE 正文查看、私钥恢复或冒充用户发消息。
- 举报仅披露用户主动确认的选定证据；E2EE 机器人或系统消息使用独立身份和密钥。
- 业务服务端 SDK 与 Rust 客户端核心分开，不导入 Service 内部包、不直连 IM 表、不持有用户 E2EE 私钥。
- 通过配置与公开 API 扩展账号映射、资料、域名、存储、限额和推送；业务卡片使用带类型、版本、大小限制的内容，由端侧加密、宿主渲染。
- Webhook 定义事件 ID、签名、时间戳、重试、去重和失败处理，不默认提供聊天明文；首期不引入复杂插件系统。

## 7. 协议、部署与独立发布

- HTTP API 使用 HTTPS + JSON/OpenAPI，实时通道使用 WSS + 版本化信封；明确鉴权、错误、设备标识、分页、游标和附件访问规则。
- 应用协议、密码协议、本地状态格式分别版本化；不支持的密码版本明确失败，不得静默降级明文。
- 首期以 Service + PostgreSQL + 持久卷运行；附件先提供持久卷实现，再扩展 S3 兼容存储。E2EE 附件仅保存密文，所有模式均执行访问控制。
- Redis、独立消息队列、微服务和 Kubernetes 不作为首期强依赖；Prometheus/Grafana 可选，容量需求出现后再扩展。
- Service 与 SDK 独立发版，维护经过验证的兼容矩阵；Rust 核心、绑定和平台二进制必须对应，未验证平台不声明支持。
- 发布附版本记录、完整性校验、许可证、必要符号和迁移说明；验证空库安装、带数据升级、备份恢复及账号/文件清理，不承诺仅换旧二进制即可回滚数据迁移。
- 最终交付须让第三方仅凭发布物和公开文档在独立工程接入；具体功能、发布包检查与升级验收统一见[功能分期与验收](功能分期与验收.md)。

## 8. 实施前待锁定

密码方案与许可证、平台/系统/架构支持矩阵、包托管与下载方式、版本兼容策略、设备授权与历史恢复、单实例容量、服务端附件存储细节和推送范围仍待锁定。端侧另需商议 TypeScript 最终桌面应用宿主、正式 Rust 绑定与预编译交付、SQLite 绑定/加密/表结构、文件位置、线程分配、回调与订阅恢复、附件编解码依赖和并发口径、浏览器持久化与多标签页规则；本次 Node 内存包的路线选择不关闭这些事项，已确认的 SQLite 与 Rust 所有权不再作为待选项。具体执行顺序见[开发路线与检查清单](开发路线与检查清单.md)。
