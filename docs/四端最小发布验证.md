## 范围与验收

本次历史实验建立同一Rust内存密码核心的Flutter、Swift、Kotlin和浏览器预编译实验包，并由独立消费工程完成真实双设备加解密。版本统一为`0.1.0-stage0.1`，只在本机打包和安装；不上传公共仓库，不确定最终产品许可证或正式密码选型，不把旧POC作为SDK运行依赖。

本项只验证双设备组及跨语言发布路线，无网络、业务登录、持久化、历史恢复、成员变更或完整IM引擎。既有安全重建与签名同步仍保留在隔离POC中，不能因本项产出平台包就声称它们已进入SDK。SDK不包含用于伪装验收的内部双设备自测：消费者分别创建端点，通过公开接口交换KeyPackage、Welcome和密文。

验收分别记录Rust测试、各目标Release库构建、包内完整性、消费工程构建、目标实际运行以及未覆盖平台。消费工程只使用已打包产物，不引用工作区Rust/SDK源码，不执行Cargo或绑定生成器；故意缺失或错版本的二进制必须失败，不自动源码编译。模拟器消费Release SDK与Release App构建分别记录，不能混为同一结果。

## 公共接口与状态

`Stage0Device`持有一个独立设备，Rust核心负责密码状态，平台层只桥接类型、错误和资源。每个对象的方法串行执行；接入方应自行调度同步原生调用，当前Kotlin消费者使用后台worker，Swift冒烟在启动回调同步执行，尚未验收UI响应性。Flutter通过生成桥接的异步执行器调用，浏览器同步密码操作的主线程限制如实记录。标识为1—64字节安全ASCII，明文为1字节—64KiB，KeyPackage、Welcome和密文最多256KiB。下表描述共同语义，语言参数与错误形式以对应包的公开类型为准。

| 操作 | 语义 |
|---|---|
| 构造`Stage0Device`；Flutter使用`newDevice()` | 在本机新建内存身份；参数为service/account/device ID，不证明业务账号归属。浏览器先`initialize()`；Flutter工厂自行等待初始化。 |
| `identityKey()` / `keyPackage()` | 返回公开签名钥及一个活动KeyPackage；重复取包复用原字节，无私钥导出。 |
| `createGroup(conversationId, peerAccountId, peerDeviceId, peerIdentityKey, keyPackage)` | 验证固定对方身份和公钥后建双设备组，返回Welcome。 |
| `joinGroup(conversationId, creatorAccountId, creatorDeviceId, creatorIdentityKey, welcome)` | 核对实例/群ID及恰好本机和指定创建者两个成员，加入新内存组。 |
| `encrypt(bytes)` / `decrypt(bytes)` | 返回密文/明文；不提供业务发送重试、队列或断电恢复承诺。 |
| `close()` | 幂等关闭并丢弃内存状态；之后密码操作明确失败。 |
| 包版本与初始化检查 | 原生绑定内部导出`sdkVersion()`；TS公开`SDK_VERSION`，Flutter公开`packageVersion`，两者由`initialize()`核对二进制；Swift/Kotlin构造器强制核对包与库版本。 |

业务外部输入先检查大小、编码和本机状态，能在密码处理前发现的错误保持原状态。OpenMLS处理Welcome可能先消耗KeyPackage；进入该步骤后出现错身份、错群或其他状态不确定失败时，对象进入不可继续使用状态，只允许关闭，不复制秘密回滚后重做。相同原则用于可能已推进密码状态的失败。错误仅输出稳定错误码及是否不可继续使用，不输出第三方错误中潜在的秘密或消息正文。

## 模块、版本与依赖

源码遵循[项目文件结构](项目文件结构.md)：`crypto-core`封装OpenMLS，薄`im-sdk`管理公开对象及串行状态，三个`bindings-*`只桥接，平台包归`src/sdk/{flutter,swift,kotlin,typescript}`；独立消费者归`tests/consumers/`，构建/运行输出归`dist/platform-release/`。

沿用已验证的Rust1.98.1、OpenMLS0.9.0及三个0.6.0配套库、wasm-bindgen0.2.128，新的workspace独立锁定依赖，不改旧POC锁文件。新增UniFFI0.31.0用于Swift/Kotlin生成类型与资源管理，flutter_rust_bridge2.11.1用于Dart异步桥接；原生手写ABI是替代方案，但本项沿既定建议栈验证生成绑定。第三方许可证与实际可达依赖随最终产物采集；生成器版本和运行依赖须一致，升级需重新生成并重新验证所有平台。

实际工具基线：Rust1.98.1、Xcode26.1.1/Swift6.2.1、iOS26.1模拟器、Flutter3.41.0/Dart3.11.0、NDK28.2.13676358、JDK21.0.10、Gradle8.14、AGP8.11.1、Kotlin2.2.20、JNA5.17.0、TypeScript5.9.3、Node26.5.0/npm11.17.0及Chrome152。Android使用专用ARM64、16KiB页模拟器；库同时构建arm64-v8a/x86_64。iOS库同时构建设备arm64和模拟器arm64/x86_64，实际运行范围另列，构建不代表对应设备已运行。

官方构建依据：[UniFFI绑定生成](https://mozilla.github.io/uniffi-rs/latest/tutorial/foreign_language_bindings.html)、[FRB预编译模式](https://cjycode.com/flutter_rust_bridge/guides/how-to/precompiled-rust)、[wasm-bindgen Web部署](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html)。本项禁止使用FRB默认的消费端源码构建回退。

## TypeScript Node 目标最小产物

2026-09-15 用户继续授权后，新增独立 Node 实验包（当前名称 `@rocket-im/stage0-node`），版本仍为 `0.1.0-stage0.1`。这是桌面 Node 宿主的 SDK 消费路线：包内附公开 JS、严格 TypeScript 声明与预编译 Rust WASM；接入者无需 Rust/Cargo 或绑定生成器。原 Web 包和历史归档保持独立。

采用 wasm-bindgen 0.2.128 的 `nodejs` 目标，生成 CommonJS 加载器；其子目录声明 `type: commonjs`，外层公开入口为 ESM。这是生成器明确支持的 Node 部署方式，WASM 不要求浏览器。此选型只覆盖当前内存能力，未将 WASM 固定为最终桌面持久化方案。[官方部署说明](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html)

不增加 Rust/npm 运行依赖，不引入 napi-rs、Electron或Tauri。继续复用同一 `im-sdk` / `crypto-core` 及锁文件；TS 仅做初始化、输入字节复制、版本核对和资源释放。同步调用放在宿主的 Node 工作线程中，按实际调用顺序执行；宿主负责关闭实例和工作线程。不会因返回初始化 Promise 而把设备方法自动变成异步任务。[Node 工作线程说明](https://nodejs.org/api/worker_threads.html)

当前范围不含完整桌面 UI、正式网络/SQLite/密钥存储或恢复；Windows与其他桌面宿主必须单独执行验收，不能由macOS或Chrome结果推定。许可证沿用原固定workspace依赖保守合集，项目分发许可仍未确定，不将最小包通过解释为正式发布。
